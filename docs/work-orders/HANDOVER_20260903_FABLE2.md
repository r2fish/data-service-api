### 2.2 (B) 台帳消化 — 契約を変えずに閉じた 4 項目

いずれも**両 peer 対称**に閉じた。契約 (`spec/`) は不変、共通 port も不変。

- **L4-5 CLOSED (P4-D16 v3、WP-B1)** — 宣言語彙 (`event_class`) の AST 走査を「**無差別 literal 規律 + 定義側 keyword-only 保証 + dict/代入の密輸禁止 + 語彙関係の厳密一致**」で再構成した。**callee 名フィルタは使わない**。走査対象は `src/<pkg>` 配下の全 `.py` の `rglob` 再帰列挙 (手書きファイル列挙は廃止)。literal の全集合 **U** に対し **`U == D ∪ N` かつ `D ∩ N == ∅`** を固定する — **D** = 宣言 `DECLARED_AUDIT_EVENT_CLASSES`、**N** = テスト内に名指しで列挙し各要素へ「耐久表へ届かない根拠」をコメントで付した非耐久除外集合 (**r2db N = 3 語** `authentication` / `control_failure` / `control_state`、**MitateDB N = ∅**)。**宣言に非耐久語彙を足して通すことは禁じてある** (`audit_query` が決して返さない語彙を公開する嘘になる)。唯一の製品コード変更は r2db `service.py` の `_event` / `_control_event` の **keyword-only 化** (呼び出し 21 件のキーワード渡し化、挙動不変)
- **L4-3 CLOSED (P4-D15、WP-B2)** — `failing` フラグは「最後に**完了した** flush 試行の結果」を表す。flush 成功時は **buffer の残量に関係なく**解除する。並行 flush の競合は**完了順序の意味論**で吸収する。**変わらないもの**: 証拠 (`count` への欠落数の累積)、alert 行の上限「flush 間隔あたり最大 1 行」、runbook の「回復は当該ペアの回復メッセージで読む」。**変わるもの (意図した代償)**: sink がフラッピングしているとき alert 行レートが「60s に 1 行」から「`alert_min_interval_s` に 1 行」(r2db 既定 2s) へ**上がり得る** — 部分的に書ける sink には証拠を早く書くほうがよく、宣言上の上限は破れない。製品コードは両 peer とも**成功分岐の 1 行**のみ
- **L4-6 CLOSED (P4-D17、WP-B3)** — HTTP conformance adapter が構築する書き手接続の `statement_timeout` / `idle_in_transaction_session_timeout` を、**peer-local テスト**で固定した。**共通 port には足していない**
- **L4-7 (i)(ii) CLOSED (WP-B3)** — MitateDB に (i) `build_control_app(env)` 経由で `MITATEDB_AUDIT_DSN` 未設定 → `unavailable` / 設定時 → `unavailable` 以外 を固定するテスト、(ii) r2db と**同名**の `test_data_plane_composition_root_does_not_import_the_control_credential_store` を追加して対称化した
- **L4-10 起票 → CLOSED (WP-B3)** — r2db `control_main` が `request_bytes` を env から読んでいなかった非対称を、`R2DB_CONTROL_LIMIT_REQUEST_BYTES` の配線で閉じた。**既定は現行の 1_048_576 を維持**する (既定値の peer 差 65536 / 1_048_576 は開示済み差として据え置き)

- **継承分** — 設計 §11 の記録のみ項目 (`audit_query` の application credential probe オラクル / in-memory・Postgres 読み手の collation 依存 / `CredentialStore.peek()` の adapter 限定)、および過去引き継ぎの台帳

### 4-4. 運用規律の継続 (第10次 §4-4 を継承 + 1 項追加)

- **完了ゲートの実測は suite を単独実行する** — 他の pytest プロセスが走っていないことを確認してから実行する。並走は PG クラスタ衝突で偽の赤を出す
- **push 前に `git log --format='%an <%ae>'` で r2fish noreply のみを確認する**
- **コミットは push とセット、さらに main へマージまでを 1 単位とする**
- **変異注入の復元は scratchpad 経由**。`git checkout` は使わない
- **(追加) コミット前に変異文字列そのものを全文 grep する** — 第10次 §5 の教訓を規律へ格上げした。本セッションの全 WP で実施し、いずれも 0 件を確認している。差分の一致確認は「消えていないこと」しか保証しない

## 5. 教訓の追加 (前書全項継承に追加)

- **綺麗な構造案は、実コードで一度走らせてから発注する**: P4-D16 の **v2 (「三方向一致」= 定義集合・呼び出し集合・宣言の突き合わせ)** は、案としては最も対称で説明しやすかった。だが独立レビューが現行コードに対して実測したところ**緑にできない**ことが判明して撤回になった — 定義集合に `append` が入り**パッケージ内のあらゆる `list.append()` が違反**になる (r2db 36 件 / MitateDB 46 件)、転送ラッパを通る MitateDB の実 emit サイト 13 件が「未知の emit 面」になる、宣言へ足せば `audit_query` が決して返さない語彙を公開する嘘になる非耐久語彙がある、の 3 つである。**構造の美しさは実測の代わりにならない。**撤回して落ち着いた v3 は「無差別 literal 規律 + 定義側 keyword-only + **名指しで審査される除外集合 N**」という、対称性では劣るが**除外の一つ一つが根拠付きで審査される**形だった。**除外を「例外」として隠すのではなく、名指しで列挙して各要素に理由を書かせる**方が、機械検査としては強い
- **受け入れ監査は、監督が変異を指定すると効く**: WP-B1 の **M7 (class 属性 literal の `Attribute` 経由 passthrough)** は、**監督が具体的な変異を指定して初めて生存が判明**した。監査側はそこから自力で **`with…as` / `except…as` / `match…as` を含む再束縛 12 形 (M8)** を見つけ、`_collect_direct_shadow_names` を個別統語形の列挙から「`event_class` という名前を束縛するあらゆる形」という一般原則へ再設計させた。結果、**テスト側の穴は 3 ラウンドで閉じ、製品コードは 1 面 (keyword-only 化) しか変わらなかった** — 第10次 §5 の「織り込みが効くほど残る欠陥は証拠側へ移る」が、台帳消化という証拠中心の WP でそのまま再現している。**監督が「この変異は生きているのではないか」と名指しできる限り、監査は自走する。**
- **記録がコードと逆になる瞬間を作らない**: WP-B2 の意味論変更は、両 peer runbook の「Known sharpness」段落を**真逆の記述にした**。これを記録 WP (WP-B4) へ回さず、**製品コードと同一コミットで直した**。回せば「main のコードは新意味論、main の runbook は旧意味論」という状態が数コミット続く — 公開リポジトリでその窓を開けない。依頼者原則 1 (先送りしない) の最も具体的な適用先は、**同一コミットに入れるべき記録を次の WP へ回さないこと**である
- **Google Drive 同期フォルダ上の作業ツリーでは、変異復元の直後に旧内容が再出現し得る**: 実装担当が 1 件観測した。同期が復元より後に走ると、ハッシュ照合を通った直後のファイルが古い内容へ戻される。**復元後は sleep を挟んで sha256 を 2 回照合する** — 1 回の照合は「今この瞬間に正しいこと」しか保証しない。これは第10次 §5 の「差分の一致確認は消えていないことしか保証しない」の、同期ストレージ版である
- **サブエージェントは長い suite を勝手にバックグラウンド化して待機に入る**: 完了ゲートの実行を委ねると、実行そのものは始まるが結果の回収で止まることがある。**監督側で log の集計行を待つ waiter を張るほうが確実**である。実測値は監督が自分で握る
- **無関係な常駐プロセスは、確認するまで無害と決めつけない**: **2026-07-28 から `pytest tests -q` のプロセス (PID 32812) が常駐している。**本セッションでは触っていないが、**PG クラスタ並走衝突の一因になり得る** — 完了ゲートを単独実行する規律は、こういう常駐が 1 つでもあると意味を失う。**依頼者に確認を仰ぐこと** (何のプロセスか、落として良いか)。第10次で「フェーズ3.5 で 2 回起きた偽の赤は 1 度も発生しなかった」と書けたのは運が良かっただけかもしれない
