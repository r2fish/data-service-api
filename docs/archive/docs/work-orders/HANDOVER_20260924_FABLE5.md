## 5. 本チャットで足した運用上の教訓

1. **大きさの目標は不可縮の床を測ってから置く。** R-104 で Evidence の目標を 2 度誤った (参照トークンだけで 57,523 文字)。文字数の目標は「参照トークン + 固定費」を先に数える。
2. **`::test_x` の path 継承は同じ主張の中の直前の `path::` に限る。** 主張をまたいで継承させると別ファイルを指す (38 件)。登録テストは名前の一意性で解決するので緑のまま通る。一度きりの検査も path を見ること。
3. **R-85 の計測 (C-03・C-06 の 113 件、`--durations=0`)**: setup 42% (1 件平均 0.49 s、application 2 つの provision)、call 44%、teardown 14%。PostgreSQL adapter のテスト実体は 479 件 (collect)。ゲート全体では setup+teardown ≈ 315 s CPU ≈ 63 s 壁時計 (12%)。template 複製で省けるのは setup の半分程度 (壁時計 20〜30 s、4〜6%)。上位 25 はすべて call 段 (C-25 13〜15 s × 4、C-27 12 s × 4、C-09 v1/v2 11 s × 8、C-05 v2 8〜16 s × 4 ≈ 250 s CPU)。
4. **台帳の版上げは同日の並走チャットと衝突する。** v1.115 が 2 チャットで重なり merge で詰め直した。並走中は起票を merge 直前まで遅らせる。
5. **版数ログの回転を忘れない** (§1.16-78: 最新 5 版)。v1.113 で忘れ、別チャットが代行した。
