## 5. 本チャットで足した運用上の教訓

1. **`conformance-tests` 全体は 600 s を超える (1104 件、606 s)。** Bash の上限 600 s で自動バックグラウンド化される。発注では 2 分割か `run_in_background` の明示を書く。
2. **文書中の pt / mutate の log 名 `pt-YYYYMMDD-HHMMSS` は公開値スキャンが project id として拾う。** `pt YYYYMMDD-HHMMSS` と書く。
3. **定数を動かす変異は、宣言・発行・期待が同一の源なら原理的に赤にならない。** 発行側だけ / 宣言側だけを動かす変異に分け、両辺同源の assert には「限界」を設計に書く (R-105 コードレビュー指摘 1・2)。
4. **同型性表の helper の cache は鍵を絶対 path にし、ガードは両 peer で relative path が同一の行から選ぶ。** `_ISOMORPHIC_TARGETS` は `AnnAssign` で matcher が拾わない。
5. **宣言 lag に従うテストは、lag の値だけが lever。** 待ち方の作り替え (Event / 短い poll) は audit_query の lag 閾値により効かない — 計測より先に「何に比例しているか」を読む。
