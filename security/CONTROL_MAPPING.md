# Security Invariant Control Mapping

Status: **Implementation mapping template**

This document maps common Security Invariants to platform-specific controls. It is intentionally not the source of truth for the invariants themselves.

| Invariant | r2db-api control/evidence | MitateDB-api control/evidence | Common conformance evidence |
|---|---|---|---|
| SI-00 Single-Compromise Containment | `r2db-api/config/authority-topology.yaml` deny-by-default plane skeleton; `r2db-api/tests/test_topology.py` negative reachability tests; production identity/network/database-grant evidence not yet present | TBD during implementation | lateral/control-plane tests |
| SI-01 Application Isolation | `r2db-api/src/r2db_api/service.py` resolves cell from `AuthContext.application_id`; `r2db-api/tests/test_foundation.py::test_server_bound_scope_and_isolation` | Preliminary local API-path evidence: `MitateDB-api/src/mitatedb_api/service.py` resolves the cell only from authenticated Principal; `MitateDB-api/tests/test_foundation.py::test_application_scope_is_server_bound`; production application authority isolation TBD | cross-Application tests |
| SI-02 Control Plane Isolation | `AuthorityTopology` denies application/developer reachability to control/provisioning; `test_topology.py`; production network/IAM evidence not yet present | TBD | control-plane denial tests |
| SI-03 Runtime/Developer Separation | `ApplicationCell.apply_schema` requires developer context; schema catalog rejects unknown runtime entity/fields; `test_runtime_developer_separation_and_structured_validation`, `test_runtime_unknown_entity_and_failed_mutation_leave_no_ghost`; topology has distinct data/development planes | Preliminary local API method/role-check evidence: `ApplicationRuntime` has no schema mutation method and `ApplicationCell._require_developer`; `test_developer_schema_and_runtime_crud`; distinct production Runtime/Developer DB authority TBD | privilege tests |
| SI-04 No Arbitrary DB Commands | `structured.py` exposes only enumerated operations and no native command API; `test_runtime_developer_separation_and_structured_validation`; contract surface review | Structured-only methods in `MitateDB-api/src/mitatedb_api/cell.py`; no command-text execution method; `test_no_arbitrary_sql_and_identifier_validation` | contract/API surface review |
| SI-05 Validated Structured Operations | `validate_identifier`, operator allowlist, typed mutation shape, and service tests in `r2db-api/src/r2db_api/structured.py` | `identifiers.py` validation, quoted identifiers and bound values in `cell.py`; `test_no_arbitrary_sql_and_identifier_validation` | injection tests |
| SI-06 Server-Bound Credential Scope | `CredentialStore.authenticate/assert_active` derives immutable `AuthContext`; `test_server_bound_scope_and_isolation` | `CredentialStore.authenticate` derives Application/role from stored credential state; `test_application_scope_is_server_bound` | scope tampering tests |
| SI-07 Compromised Credential Containment | Topology deny rules plus per-credential role/scope records; negative topology and isolation tests; production containment evidence not yet present | TBD | stolen-credential scenario tests |
| SI-08 Bounded Resource Consumption | finite `ResourceLimits` across required classes; atomic credential-rate window, `_slot`, iterative request/depth checks, structured batch/result/schema checks, and wall-clock deadline enforcement; `test_request_body_limit_has_a_deterministic_boundary`, `test_deep_cyclic_and_oversized_requests_are_rejected_without_recursion_or_repr`, `test_every_advertised_resource_limit_has_a_deterministic_boundary`, `test_rate_limit_is_atomic_for_concurrent_requests`, `test_schema_deadline_failure_rolls_back_entity_catalog_and_revision`; capability status labels identify enforcement layer | Local bounds for batch/result/fields/filters/schema/request-size in `FoundationConfig` and `MITATEDB_*` config; `test_bounded_inputs_and_explicit_destructive_confirmation`; execution-time/concurrency/rate remain unimplemented | resource boundary tests |
| SI-09 Controlled Destructive Operations | `structured.py` requires operation-specific confirmation for delete/drop; `test_atomic_rollback_and_explicit_destructive_operation` | `delete` requires explicit confirmation and non-empty filters; `test_bounded_inputs_and_explicit_destructive_confirmation` | destructive misuse tests |
| SI-10 Error/Information Non-Disclosure | `FoundationError` emits safe problem shape; malformed/deep/cyclic input tests verify structured safe failures; no internal exception serialization; audit tests check secret absence | TBD | error probing tests |
| SI-11 Atomic Integrity | `ApplicationCell.transact` snapshots and restores on failure; `test_atomic_rollback_and_explicit_destructive_operation` | `ApplicationCell.transact` uses one local transaction with rollback on rejected operation; `test_transaction_rolls_back` | rollback/fault tests |
| SI-12 No Data-Service Bypass | Structured package has no credential/connection/native-command response; topology denies privileged egress; contract smoke test | TBD | exposure/config review |
| SI-13 Revocation/Disable Effectiveness | `CredentialStore.assert_active` re-checks each operation and `DataService` checks application state; `test_revoke_disable_and_unavailable_state_fail_closed`; propagation bound remains deployment evidence | `CredentialStore.assert_active` re-checks revocation/application state on every session operation; `test_disable_revoke_and_unavailable_state_fail_closed` (local API-path evidence; production propagation bound TBD) | revoke/retry tests |
| SI-14 Security-Relevant Auditability | `ControlAuthority` emits canonical lifecycle/control-failure events including denied audit deletion; application facade exposes no audit accessor; `AuditSink` immutable snapshots and forbidden-field guard; `test_control_lifecycle_and_failures_are_canonical_audit_events`, `test_audit_is_append_only_and_secret_free`; external append-only sink and sink-failure policy not yet deployed/evidenced | Preliminary local API-path evidence only: `AuditSink` uses immutable snapshots and detail/event allowlists; representative secret/row-value test in `test_audit_events_are_append_only_and_secret_free`; no external append-only authority is implemented or evidenced, production append-only authority/log sink TBD | audit evidence tests |
| SI-15 Fail-Closed Authorization | `CredentialStore` rejects unavailable/unknown/disabled/revoked state; `DataService._check`; `test_revoke_disable_and_unavailable_state_fail_closed` | `CredentialStore` rejects unavailable auth state and missing/disabled credentials; `test_disable_revoke_and_unavailable_state_fail_closed` | unavailable/invalid auth-state tests |

## Rule

A blank/TBD mapping is not permission to weaken an invariant. It means the implementation has not yet demonstrated how it satisfies the common requirement.

Conversely, a new implementation control does not require a new invariant if it preserves the existing security outcomes.
